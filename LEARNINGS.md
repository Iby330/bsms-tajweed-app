# Learnings

Durable, cross-cutting knowledge base of failures and learnings from running skills,
directives, and execution scripts in this workspace. Unlike the ephemeral per-skill
journals (`.claude/skill-research/<name>/journal.md`, which get consumed and archived),
this file is permanent and NOT scoped to one skill — it's for things worth knowing
before starting ANY new task, building a new skill, or redoing an old one, in this
chat or a brand new one.

**Read this before:** building a new skill, redoing a task that failed before, or
starting work in a new domain covered below.

**Write to this when:** the reviewer (`directives/improve_skill.md`) finds a
journalled problem that's broadly reusable — not specific to one skill's internals,
but a fact about an external API, a tool, an environment quirk, or a failed approach
that would bite ANY future skill touching the same thing. One line per entry, most
recent first within its section. Skill-specific fixes stay in that skill's own
directive/changelog instead — only promote here if a *different* skill could hit it too.

This file is also periodically pulled into a cross-workspace global learnings digest
(`~/.claude/GLOBAL_LEARNINGS.md`) — keep entries self-contained (a reader from a
different project should understand each line without extra context).

## APIs & external services

- [2026-07-31] Supabase: the CLI is NOT installed on this machine. Apply SQL/migrations via the Management API — `POST https://api.supabase.com/v1/projects/<ref>/database/query` with `Authorization: Bearer $SUPABASE_ACCESS_TOKEN` and `{"query": "..."}`. Success is 201 + a JSON array; non-2xx must be treated as failure (body carries `message`). Wrapped in `execution/apply_migration.ts`. (source: apply_migration)
- [2026-07-31] Supabase Storage: overwriting an object (`upload(..., {upsert: true})`) is an UPDATE on `storage.objects`, so an insert-only RLS policy fails with a policy violation. Any bucket users re-upload to needs UPDATE *and* DELETE policies, not just INSERT. (source: voice notes)
- [2026-07-31] Supabase: `upsert(..., {onConflict: "a,b"})` needs a real UNIQUE INDEX on exactly those columns, and Postgres needs BOTH insert and update RLS policies for the upsert to pass. (source: voice notes)
- [2026-08-06] YouTube **private** videos cannot be embedded anywhere — no API key, link format or invite makes them work in an iframe. **Unlisted** embeds fine and is still hidden from the channel's Videos tab and from search. Any course video that shouldn't be public must be Unlisted, never Private. Corollary: a lesson missing from the public channel may only be unlisted, in which case it needs nothing but its id. (source: course video grid)
- [2026-08-06] YouTube thumbnails need no API key: `https://i.ytimg.com/vi/<id>/hqdefault.jpg`. Use `hqdefault` (always exists, 480×360, 16:9 content letterboxed with 12.5% bars) over `maxresdefault` (true 16:9 but only exists for HD-sourced uploads — a 404 is worse than a crop). `object-cover` in a 16:9 box crops exactly 12.5% each edge, i.e. precisely the bars. (source: course video grid)
- [2026-08-10] Netlify: creating a site via `POST /sites` with a `repo` payload does **not** establish the GitHub App connection. The site comes back with `build_settings.installation_id: null` and the first build dies at stage "preparing repo" with `Host key verification failed` — which reads like an SSH/deploy-key problem but is really a missing App link. Pass `installation_id` explicitly, reusing the one from any already-linked site on the account (`GET /sites` → `build_settings.installation_id`). (source: netlify-deploy)
- [2026-08-10] Netlify env vars on the free/dev plan cannot be marked secret, and the two limits mask each other: sending an explicit `scopes` list 403s with "Upgrade your Netlify account to set specific scopes", and `is_secret: true` with default scopes 422s with "Secrets are not allowed to run in 'post_processing' scopes" — because secret requires dropping post_processing, which requires custom scopes. Set them as plain vars and tell the user they're readable in the Netlify UI. (source: netlify-deploy)
- [2026-08-10] Netlify + Next.js: secrets scanning greps the *build output* for env var values and fails the build on a hit. `NEXT_PUBLIC_*` values are inlined into the client bundle by design, so they always hit. Set `SECRETS_SCAN_OMIT_KEYS` to the public keys (here `NEXT_PUBLIC_SUPABASE_URL,NEXT_PUBLIC_SUPABASE_ANON_KEY`) or every build fails on a non-problem. (source: netlify-deploy)
- [2026-08-10] Regenerating `web/src/lib/database.types.ts` after a schema change: there is **no typegen npm script** and the Supabase CLI is not installed. Use the Management API — `GET https://api.supabase.com/v1/projects/<ref>/types/typescript` with `Authorization: Bearer $SUPABASE_ACCESS_TOKEN`, which returns `{"types": "..."}`. Two things to know: it does NOT emit the `graphql_public` schema block the committed file used to carry (harmless — no app code references it), and it DOES add views that are revoked from `authenticated` (`v_hw_pct_all`, `v_hifz_progress_all`). Symptom of stale types is a confusing `SelectQueryError<"column 'x' does not exist on 'view'">` at every property access, not at the `.select()` call. (source: leaderboard scopes)
- [2026-08-19] **Do not verify a Netlify deploy with `curl` on an SSR route.** `curl https://bsms-tajweed.netlify.app/` was served a *stale cached* SSR HTML page referencing a superseded `/_next/static/chunks/<hash>.css`, and that chunk 404'd (9-byte body) — which reads exactly like "the deploy failed" and cost ~20 minutes of polling. A real browser hitting the same URL at the same moment got the current HTML and the current chunk (`0psvvdai63wf8.css`, 127KB) with zero failed requests. The Netlify MCP connector is no help either: `get-projects` for `bsms-tajweed` returns `[]`. Verify by driving a browser and reading the CSS it actually loads — hook `page.on("response")`, filter `.css`, and grep the text for a class the new build introduced. Do not compare local `.next/static/chunks/*.css` hashes against production's; the two builds hash differently even from the same commit. (source: homework summary strip)
- [2026-08-10] The Netlify MCP connector's `get-projects`/`get-project` served a full, plausible record for a site that had been **deleted** — name, URL, team, even a last-deploy id and commit. Every direct REST call 404'd and the live URL returned a bare 50-byte "Not Found". Don't trust the connector as proof a site exists; confirm with `GET /sites/<id>` or by loading the URL. (source: netlify-deploy)
- [2026-08-12] PostgREST embeds between tables joined by **more than one FK** (e.g. profiles↔classes via `profiles.class_id` AND `classes.teacher_id`) fail at **runtime** with HTTP 300 / PGRST201 unless the select carries an FK hint (`classes!profiles_class_id_fkey(name)`). supabase-js **types accept the bare form**, so tsc and vitest stay green while every call returns an error — `currentProfile()` resolved null for all users and would have bounced everyone to /login. Any new embed on a multi-FK pair needs the hint AND a live probe (`.select(...).limit(0)` and check `.error`). Same trap: string-concatenated select strings widen to `string` and silently kill postgrest-js type inference — use one template literal. (source: perf overhaul)
- [2026-08-17] Supabase/PostgREST REST endpoint (`/rest/v1/<table>`) caps a single request at 1000 rows by default, with no error or truncation flag — a plain `select` against `quran_words` (5964 rows for pages 562-604) would have silently returned only the first 1000. Any bulk read via the raw REST API (not supabase-js, which some call sites paginate for you) needs an explicit offset/limit loop that continues until a batch comes back shorter than the page size. See `execution/audit_mushaf_measure.py`'s `fetch_words` for the pattern. (source: audit_mushaf_measure)
- [2026-08-12] Next 16 `revalidateTag` requires a second "profile" argument (`revalidateTag("tag", "max")`) — the single-arg form is deprecated and `"max"` is the recommended stale-while-revalidate profile, available without cacheComponents. `unstable_cache` still works with cacheComponents off; `"use cache"` does not. (source: perf overhaul)
- [2026-08-12] A `"use server"` file may only export **async functions** — exporting a pure sync helper from an actions file passes tsc and vitest but fails `next build` (SWC error). Put pure planning/helper logic in a sibling module (the repo convention: `marking/plan.ts` next to `marking/actions.ts`). (source: perf overhaul)
- [2026-09-22] **Supabase personal access tokens expire mid-session, silently.** `SUPABASE_ACCESS_TOKEN` in `.env` worked for a migration and then, ~40 minutes later in the same session, every Management API call (migration *and* `--check`) returned `401 {"message":"Unauthorized"}` — which reads like a SQL/permissions problem but is purely the credential. Any script using that token hits this, not just `apply_migration.ts`. Fix: new token at https://supabase.com/dashboard/account/tokens, replace the `.env` line. Workaround without a new token: the supabase MCP `apply_migration` tool — but it does not write the repo's `schema_migrations` ledger, so insert that row by hand afterwards or the ledger drifts from the database. (Distinct failure: a 401 whose body says "Format is Authorization: Bearer [token]" means the token is *mangled*, e.g. an inline `#` comment in `.env`, not expired.) (source: apply_migration)

## Tools & environment

- [2026-09-22] **iOS 26 Safari ignores `<meta name="theme-color">`.** Without `viewport-fit=cover` it paints solid bands behind the clock and its floating toolbar, which reads as the page being cut off. With cover the page runs under both (every edge-touching surface must pad itself with `env(safe-area-inset-*)`), but AT SCROLL TOP the band behind the clock is still ONE SOLID COLOUR sampled from the page, never the page's own pixels — a background pattern cannot continue there on any site (rahmaniyyah.com shows the same). Scrolled, Safari shows the page through a fade. Setting `html` background alone changed nothing on-device; the band followed `body`'s background. Match the colour the page LOOKS (here #00004d lifted ~3% by a screen-blend grain overlay, measured from phone screenshots with PIL), not the token. No Simulator on this Mac: test via the phone on Wi-Fi at `http://<mac-ip>:3100` with `next start -H 0.0.0.0` (sign-in won't work over plain http). (source: mobile edge-to-edge fix)
- [2026-07-31] Playwright/chrome-devtools MCP here attaches to an EXISTING Chrome on port 9222 rather than launching one — if nothing is listening it fails with `ECONNREFUSED 127.0.0.1:9222`. Start one yourself: `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --remote-debugging-port=9222 --headless=new --user-data-dir=<scratch>`, as a harness background job (a trailing `&` inside a one-shot shell dies with that shell). The app was "Google Chrome 2.app" until 2026-09 and is now plain "Google Chrome.app"; if the launch exits 127, `ls /Applications | grep -i chrom`. Add `--use-fake-device-for-media-stream --use-fake-ui-for-media-stream` to test microphone features and `--autoplay-policy=no-user-gesture-required` for video. (source: BSMS UI verification)
- [2026-07-31] Two agent sessions sharing one CDP browser fight over the same login cookie — you get silently signed out and reauthenticated as the other session's user mid-test. If sign-in state flips unexpectedly, suspect a second session before debugging the auth code. (source: BSMS UI verification)
- [2026-07-31] `tsx` does not load `.env.local`. Read it manually (see `execution/seed_demo.ts`) rather than assuming `process.env` is populated. (source: eval_marking)
- [2026-08-06] `tsx` on a script OUTSIDE `web/` (e.g. a scratchpad file) compiles as CJS and rejects top-level `await` — "Top-level await is currently not supported with the cjs output format". Wrap the body in `async function main() { … } main();` rather than moving the file. (source: apply_migration)
- [2026-08-06] **`grep` silently finds nothing in `web/src/lib/curriculum/tree.ts`.** It embeds a raw NUL byte as its composite-key separator (`` `${termId}\0${series}` ``), so `file` reports "data" and grep treats it as binary — printing no matches and NO error. Use `grep -a` on it. The code is correct and its 44 tests pass; this is a search trap, not a bug. Note the Read tool renders the NUL as a space, so the file looks normal when read. (source: course video grid)
- [2026-08-06] macOS/BSD `grep -E` does not support `\s` — it matches nothing instead of erroring. Use `[[:space:]]`. Together with the NUL issue above, this is two ways to get a *silent false negative* while checking whether a symbol exists. Confirm a "missing" symbol a second way before acting on it. (source: course video grid)
- [2026-08-16] **Netlify re-appends the request's query string to a 307 redirect; local Next does not.** `/auth/confirm?token_hash=…&next=%2Fwelcome` returns `location: /welcome` on `next dev` but `location: /welcome?token_hash=…&type=…&next=…` in production, so the spent auth token ends up in the address bar and browser history. The route is not at fault — `new URL("/welcome", request.url)` drops the base's query per the URL spec, and `node -e` confirms it. Only the success path shows it; a failing token redirects to `/forgot-password?error=link` cleanly on both, because that URL carries its own query. Harmless (the token is single-use and already redeemed) but do not waste time hunting it in the route code. (source: invite flow verification)
- [2026-08-19] **`npm run build` and `next dev` share `web/.next` and the build wins.** Running a production build to verify something while the dev server is up rewrites `.next/static` under it; the running server keeps serving HTML that points at client chunks the build has just deleted, and the browser dies with `ChunkLoadError` or a blank page while `curl` of the same route still returns 200 (SSR is fine — it is only the client bundle that is missing). Fix: `pkill -f next-server`, `rm -rf web/.next`, restart `npm run dev`. Better: don't build while dev is running; if you need built CSS for an isolated check, build first, copy the chunk out, then restart dev. Related, and separate: **the first request to a route on a cold dev server can render the 404 page while Turbopack is still compiling it** — the log says `GET /teacher/homework/1 200 in 2.1s` and the browser shows "This page could not be found". Always hit a dev route twice before believing a 404. (source: homework summary strip)
- [2026-08-16] **Next 16 caches optimised images at `.next/dev/cache/images`, not `.next/cache/images`.** Replace a file in `public/` and `next/image` keeps serving the old bytes across dev-server restarts and fresh browser profiles — `curl /brand/logo.png` returns the NEW file while `curl "/_next/image?url=%2Fbrand%2Flogo.png&w=96&q=75"` returns the OLD one with `X-Nextjs-Cache: HIT`. Deleting the Next-15 path is a silent no-op (nothing to delete, no error). Fix: `rm -rf .next/dev/cache/images` then restart. Diagnose by comparing those two curls; the cache filenames embed the source ETag (`W/"<hex size>-…"`, base64'd), so decoding it tells you which version is stored. (source: cream logo swap)
- [2026-08-17] Probing a DOM node's natural (unconstrained) width by cloning it in the browser: setting `probe.style.cssText = "..."` on the clone wipes React's inline `font-family`, so the page-specific font falls back silently and measured widths come out ~40% short (5-8em instead of 14-15em) — reads exactly like a real finding. Copy individual style properties onto the clone instead of replacing `cssText` wholesale. (source: audit_mushaf_measure)
- [2026-07-31] Next.js 16 renamed Middleware to **Proxy**: the file is `src/proxy.ts` exporting `proxy()`, it defaults to the Node runtime, and setting the `runtime` config option there throws. Bundled docs live in `node_modules/next/dist/docs/` — read them, this version differs from training data. (source: session refresh)

- [2026-09-13] **`execution/apply_migration.ts` writes a `schema_migrations` ledger row named after every file it runs** — so running an ad-hoc read-only probe through it by dropping SQL in a temp file leaves a junk row (`q.sql`), and the follow-up delete you write to clean that up leaves its own row in turn. The ledger insert is `on conflict (filename) do update set applied_at = now()`, so the loop only closes by naming the cleanup file after a REAL migration. Use `--probe` (added 2026-09-13) for any ad-hoc query: `npx tsx execution/apply_migration.ts --probe "select …"` takes inline SQL or a file, prints the full JSON result, and touches no ledger. (source: apply_migration)

- [2026-09-21] **`uthmanic_hafs_v22` (web/public/fonts) has NO glyph for U+0622 ALEF WITH MADDA ABOVE (آ)** — it maps to `.notdef`. In fontkit/any glyph-level pipeline the letter silently vanishes (.notdef has no outline, so nothing is drawn and nothing errors); in a browser it would instead fall back to another font mid-word. Write it decomposed, U+0627 + U+0653 (ا + ٓ), which the font shapes correctly, and make any shaping script throw on glyph id 0 / `.notdef` rather than skip it. Other precomposed Arabic codepoints may have the same gap — check `font.glyphForCodePoint(cp).id !== 0` before trusting one. (source: bake-ayah)
- [2026-09-21] **fontkit does not do HarfBuzz's Arabic mark reordering.** HarfBuzz remaps SHADDA's combining class 33 -> 27 (`hb-unicode.hh`, "modified combining class") so it sorts BEFORE fatha/damma/tanwin (ccc 27-32); the font's mark-to-mark lookups then stack the vowel ON TOP of the shadda. fontkit shapes text in plain Unicode canonical order, so a vowel lands at the shadda's own height (~25u below where browsers put it ~300u higher) — wrong, and easy to miss. Fix: stable-sort each mark run by the modified CCC before calling `font.layout()` and keep a permutation back to the stored text (see `reorderMarks()` in `web/scripts/bake-ayah.ts`); guard by asserting every above-vowel's y > its shadda's y. Kasra draws below, so exclude it from that check. (source: bake-ayah)
- [2026-09-21] fontkit glyph -> source-character mapping is NOT a sequential walk: shaping ligates letters across an intervening mark (in يَـٰٓأ the ya+tatweel become one glyph while the fatha between them is its own glyph), so one glyph can own non-contiguous characters. Assign each glyph's codepoints to the earliest UNCONSUMED matching source char within a small lookahead, then assert every char was claimed exactly once. (source: bake-ayah)
- [2026-09-21] **Remotion `<Player autoPlay>` fails SILENTLY in real Chrome** — the hero sat on frame 0 with no console error, while it played fine in the Claude desktop app's built-in browser (more permissive autoplay policy), so preview-pane checks did not catch it. The Player prepares for audio by default (shared audio tags, unmuted) and Chrome blocks unmuted playback before a user gesture. For any silent composition pass `initiallyMuted` and `numberOfSharedAudioTags={0}`, and also call `playerRef.current.play()` in an effect after mount rather than trusting `autoPlay` alone (see `web/src/components/landing/tajweed/TajweedHeroPlayer.tsx`). Verify autoplay in real Chrome, not only the preview pane. (source: tajweed hero)
- [2026-09-22] **No Homebrew, so no system ffmpeg.** A standalone arm64 build (martin-riedl.de, v9.0.2) lives at `.tooling/ffmpeg/ffmpeg` and `.tooling/ffmpeg/ffprobe` — git-ignored, so a fresh clone won't have it; re-download from `https://ffmpeg.martin-riedl.de/redirect/latest/macos/arm64/release/ffmpeg.zip` (and `ffprobe.zip`) and clear `com.apple.quarantine`. Raw testimonial footage goes in the git-ignored `testimonials-incoming/` at repo root — the repo is public, so only compressed, consented cuts may land in `web/public/testimonials/`. (source: landing testimonials)

- [2026-09-22] **Headless Chrome will not lay out narrower than 500 CSS px.** `--window-size=390,844` renders the page at 500px wide and crops the screenshot to 390, which looks exactly like a horizontal-overflow bug on every phone-width page; `--force-device-scale-factor` does not help (window size is in DIPs, so innerWidth stays 780 at dsf 2). Two real phone-width pages were "diagnosed" as broken this way before a probe page printing `innerWidth` exposed it. Headless also reports `prefers-color-scheme: dark` by default: pass `--blink-settings=preferredColorScheme=1` for light. (source: brand/design audit)
- [2026-09-22] **A browser can be driven without installing puppeteer or playwright.** Start Chrome with `--headless=new --remote-debugging-port=9222 --user-data-dir=<tmp>`, `PUT /json/new?<url>` to open a target, then speak CDP over Node 24's global `WebSocket` (`Page.navigate`, `Runtime.evaluate` with `awaitPromise`+`returnByValue`, `Page.captureScreenshot`). ~60 lines, no download. React inputs need the native value setter plus a bubbling `input` event, or `onChange` never fires. Used to test the whole apply → place → Send login → set password flow through the real UI. (source: signup flow end-to-end test)
- [2026-09-22] **Deleting a test teacher fails with an empty error object until every reference is cleared.** `auth.admin.deleteUser` returned `{}` because `applications.reviewed_by` still pointed at that profile (plain FK, no ON DELETE), and the preceding `profiles` delete had silently failed for the same reason. Null the referencing columns first, then delete the profile, then the auth user. The empty error body says nothing; check the FKs. (source: signup flow end-to-end test)
- [2026-09-18] **Phone screenshot harness: `web/scripts/screenshots.mjs`.** Order is `npm run shots:seed` (creates a throwaway teacher and a classless throwaway student over the Supabase admin API, credentials to the gitignored `web/.playwright/seed.json`), then `npm run shots:login -- student` and `... -- teacher` (saves a Playwright storage state per role), then `npm run shots` (390x844 at 2x, light and dark, viewport plus fullPage PNGs into `web/screenshots/<role>/<theme>/`); `npm run shots:teardown` deletes both users. Pass `--base http://localhost:3010` to every command when port 3000 is busy. Three things that bite:

  - **The sign-in straight after a seed can fail as 'Incorrect email or password'.** The login form flattens every auth error to that one string, and Supabase rate-limits its auth endpoint right after the two admin `createUser` calls. - [2026-09-19] **Ad-hoc Playwright probes must live under `web/`, as `.cjs`.** A throwaway script in `/tmp` or the scratchpad resolves neither `playwright` nor `@playwright/test` by bare name (node looks up from the script's own directory), and the installed `@playwright/test` is CJS, so importing `web/node_modules/@playwright/test/index.mjs` by absolute path gives no named `chromium` export either. Cost four retries in one session. Write the probe as `web/probe.cjs` with `const { chromium } = require("@playwright/test")`, or drive `web/scripts/screenshots.mjs --routes` instead. (source: mobile-pass)
- [2026-09-19] **`web/` tests have no `@testing-library/jest-dom`** (`vitest.config.ts` declares no `setupFiles` and the package is not a dependency), so `expect(el).toHaveAttribute(...)` fails with `Invalid Chai property: toHaveAttribute` — which reads like a broken element, not a missing matcher. Assert with plain DOM: `expect(el.getAttribute("aria-label")).toBe("…")`. Same for `toBeInTheDocument`, `toHaveClass` and friends. (source: mobile-pass)

## Failed approaches (don't retry these)

- [2026-07-31] YouTube IFrame API: driving watch-progress off `onStateChange` (wait for PLAYING, then poll) did not fire at all under CDP — the events never reached the handler. Poll `getCurrentTime()/getDuration()` on a plain 1s interval started right after the player is constructed instead; it is a direct call, always truthful, and also survives backgrounded tabs, fullscreen handoff and seeking. (source: lesson player)
- [2026-07-31] Importing anything from `web/src/lib/**` into a Node/tsx script fails if the module chain includes `import "server-only"`. Don't copy the module to work around it — the copy silently drifts from production. Shim it: resolve `server-only` and put an empty module in `require.cache` before requiring the real file. (source: eval_marking)

## Reusable patterns / gotchas

- [2026-07-31] Any eval/aggregation harness must report WHY rows were dropped, with counts. A first run here silently discarded ~50% of responses (zero-mark free-text items have no rubric, so the marker returned null and the whole response was condemned unmarkable) and still printed a confident-looking accuracy figure computed on the skewed remainder. Silent skips look identical to "nothing went wrong". (source: eval_marking)
- [2026-07-31] Google Forms only ever exported a TOTAL per response, never per-question marks. Any accuracy comparison against the 2025/26 gradebook is therefore total-vs-total, and is only fair on homeworks where the engine can mark every graded question unaided — exclude the rest explicitly and name them. (source: eval_marking)
- [2026-07-31] Verify a feature by exercising it, not by reading it. Testing this build surfaced three things inspection had missed: `/lessons/[id]` was linked from two screens but the route did not exist, teachers had no sign-out control anywhere, and `/locked` was redirected to but never created. (source: BSMS v1 gap fill)
- [2026-08-06] Address data migrations by stable POSITION — here `(series, term, week)` — never by title match. Live lesson titles had already drifted from what the `0003` seed wrote (colon vs em dash, from a later Forms re-import), so a title-matched `UPDATE` would have matched zero rows and still reported success. (source: 0008_lesson_videos)
- [2026-08-06] Probe the live DB read-only BEFORE writing a data migration. Doing so here found `lessons.youtube_id` on Tajweed 1 set to `M7lc1UVf-VE` — Google's IFrame-API demo video, left over from building the player and serving to real students. No test caught it because no test asserts on production data. (source: 0008_lesson_videos)
- [2026-08-06] Postgres enum columns don't compare to text literals: `lessons.series` is `series_t`, so `l.series = v.series` from a `VALUES` list fails with `operator does not exist: series_t = text`. Cast the LITERAL to the enum (`v.series::series_t`), not the column to text — a typo'd key then errors as an invalid enum label instead of silently matching no rows. (source: 0008_lesson_videos)
- [2026-08-06] Attaching real lesson videos CHANGES existing completion figures, because a module with a watchable video now requires watching it. Term 1 Tajweed went from "8 of 8 complete" to "1 of 8" the moment the videos landed.
